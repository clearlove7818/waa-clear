# 界面规则 · for-web-dev

适用于网页和应用界面上给用户看的文字：按钮、标签、提示、报错、通知、空状态、页面正文。手机应用和桌面应用的界面文字同样适用。

按“谁看”判断是否属于本场景：存在数据库里、最终显示给用户的文字（通知模板、标签名）属于本场景；服务器日志、代码注释属于 for document。

通用规则（[`for-all.md`](for-all.md)）同样适用。

必须完整读取本文件及 [推荐词表](../dictionary/recommended.yaml)。技术／产品界面适用时读取 [tech-doc 协作](../references/tech-doc-compatibility.md)并按可用专门规则处理。文案任务不授予开发、上线或账户操作权限。例子是演示；实际原因、步骤、恢复与不可逆性须有产品依据。

<a id="w1"></a>
### W1 不用含糊复数人称和第三人称

界面文字默认不得用找不到明确对象的复数／第三人称：“我们、你们、他们、她们、它们、咱们、大家、他、她、它”。要说谁必须写名称。固定用户原话、项目明确允许的品牌文案保持原样；不是把词语匹配当作事实错误。

原因：界面上同时出现用户、用户所在的公司、产品方和其他对象，复数代词指的是哪一群，读者要猜。按钮、提示、报错常常单独出现，第三人称代词找不到所指的词。

- ✗ 账号已停用，请联系我们。
- ✓ 账号已停用，请联系客服。
- ✗ 大家分的是同一块蛋糕。
- ✓ 各品牌分的是同一块蛋糕。
- ✗ 当前账号没有它的查看权限。
- ✓ 当前账号没有这份报表的查看权限。

<a id="w2"></a>
### W2 “你”指用户，“我”只出现在用户的原话里

需要第二人称时，“你”必须只指正在使用产品的人。“我”默认只在用户自己说的话里；项目明确的固定标签与用户原话优先。“你”和“您”二选一，在任务覆盖的界面里保持一致；未检查全站就不声称全站统一。技术成品可按专门规则改用无主句或明确角色。

原因：产品代用户说“我”和产品方自称混用，会让动作主体不清。

- ✗ 诊断我的网站（按钮上的“我”指用户，旁边“联系我们”的“我”又指产品方）
- ✓ 诊断网站

<a id="w3"></a>
### W3 按钮以动词开头，用推荐的动作词

按钮文字必须以动词开头，宜不超过 6 个字。动作词宜使用推荐词表里的词，同一个动作全站必须使用同一个词。

说明：推荐词表给删除、移除、清空这类动作词各定了一个意思，见 [`recommended.yaml`](../dictionary/recommended.yaml)。

必须按 [词表语境裁决](../dictionary/README.md#applicability)核对真实操作；“删除”不等于产品必定不可恢复，“取消”也不证明中间结果不保留。按钮名称沿用项目和产品实际功能，不凭示例更换动作。

原因：按钮让用户预测接下来的动作；6 字只是长度推荐，必要对象和风险不删。

- ✗ 立即提交审核申请吧
- ✓ 提交审核

<a id="w4"></a>
### W4 同一个功能在各处同名

同一个功能在导航、标题、按钮、提示和帮助文档里必须使用同一个名称。

原因：不同名称会被误读成不同入口。任务只覆盖部分表面时注明覆盖范围，不假装已核对未见页面。

- ✗ 导航叫“项目”，按钮写“新建工程”。
- ✓ 导航叫“项目”，按钮写“新建项目”。

<a id="w5"></a>
### W5 报错说清发生了什么、接下来能做什么

报错必须说清两件事：发生了什么，用户接下来能做什么。报错不得只给错误代码，不得责怪用户。

原因已知时说明已知原因；仅有 500、超时或“异常”不能证明网络中断。原因未知就写未知，保留有用错误原文。恢复动作必须与实际能力一致，不编重试间隔、成功保证或新的权限动作；没有已知恢复方式时，仅在真实支持入口或诊断信息有用且可用时提供。没有已知的下一动作时，可只说明失败和未知原因，并在审稿缺项中注明恢复信息未提供，不为满足“两件事”造动作。部分保存可能已发生时，保留该状态，不把“失败”改成“未保存任何内容”。

原因：用户需要知道影响和恢复，而虚构根因会把人带向错误操作。

- ✗ 操作失败（500）。
- ✓ 确认网络中断且重试受支持时：保存失败：网络连接中断。检查网络后重试。
- ✓ 只有错误码时：保存失败（500），原因尚未确定。请保留错误码供排查。（仅在保留错误码确有用途时）
- ✗ 你输入错了。
- ✓ 请输入 11 位手机号码。

<a id="w6"></a>
### W6 空状态区分未创建、筛选、权限与加载失败

确实尚未创建内容时，空状态必须说明这里将出现什么，以及产品已支持的开始动作。空白是筛选无结果、无权限或加载失败时，必须说明对应状态，不强推“创建第一份报告”。原因不明时标明未确定，不能凭空白判断用户没有数据。

原因：不同空状态需要不同恢复；错误引导可能重复创建或掩盖权限边界。

- ✗ 暂无数据。
- ✓ 还没有报告。完成第一次诊断后，报告会出现在这里。
- ✓ 当前筛选条件下没有报告。（资料未提供“清除筛选”控件时不编这个按钮）
- ✓ 当前账号无权查看报告。（无创建引导）

<a id="w7"></a>
### W7 说明文字讲“是什么、怎么读”，不藏操作

说明文字（悬停提示、信息图标里的文字）必须回答“这是什么、怎么读”。怎么操作必须由控件本身表达，不得写进说明文字。

原因：提示解释数值和对象，控件承载动作。安全前提或控件无法承载的必要操作帮助可在独立帮助说明中明确写出，不为删字移除可访问性信息。

- ✗ 点击任意一行可以查看明细。这个数字表示提到你的回答占全部回答的比例。
- ✓ 提到你的回答占全部回答的比例。

<a id="w8"></a>
### W8 一句界面文字写成一个完整的字符串

一句界面文字必须写成一个完整的字符串模板，不得拼接句子片段。

原因：拼接出来的句子，检查和翻译时都拿不到整句；换成其他语言时语序也会出错。

- ✗ `'已选择' + count + '个文件'`
- ✓ `'已选择 {count} 个文件'`

占位符、JSON 键、代码标识和模板语法必须保持原样。只有文案任务明确覆盖的可见字符串能改；检查器提取到代码字符串不构成改代码或改机器字面量的授权。

<a id="w9"></a>
### W9 页面文字服务当前用户

界面上的每句话必须说明当前对象、结果、操作或必要边界。制作标签、验收结论和设计取舍不放进面向用户的正文；已有任务授权的开发记录可保留必要依据，不自动新建记录。用户明确要求的比较、证据和真实示例边界按 G20 保留。

审阅必须覆盖实际渲染的标题、正文、按钮、提示、图注和角标。按 G20 判断每句话是否必要，不能只检查术语和标点。

原因：源码字符串可能未显示，也可能被条件、裁剪、拼接或翻译改变。实际渲染无法查看时，分别说明已做源码／字符串审阅和未验证的表面检查，不把 CLI 结果称作渲染覆盖。演示数据、价格范围、权限与真实风险边界须保留；已有授权开发记录可放制作依据，不自动写记录。

- ✗ 在正式产品首页写“当前页面仅用于展示功能布局”。
- ✓ 删除该句，用实际功能和操作说明组织页面。
- ✓ 示例数据，仅用于说明报表格式。（读者需要区分示例与真实数据。）
