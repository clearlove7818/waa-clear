# waa-relax-go

完整中文规则，加上容易继续、容易开始的交互。用于写、改、校、审中文、统一术语、整理回执和把指导拆成可操作步骤；不以短代替完整，不诊断读者，也不改机器字面量。

这是个人维护的技能包，不代表上游发布或合规认证，也不替换独立 `tech-doc-style-chinese`。仓库内容更新不等于宿主安装或激活验证。

本仓库由 `waa-clear` 更名为 `waa-relax-go`，沿用同一个 GitHub 仓库并保留原提交历史。新版替代旧版，不需要同时维护两套成品。仓库地址：[clearlove7818/waa-relax-go](https://github.com/clearlove7818/waa-relax-go)。

## 怎么使用与停止

直接给能读取完整目录的宿主表达请求，例如：

```text
用 waa-relax-go 改这段中文，保留数字、条件、否定和原意：……
```

不含名称的“说清楚一点”“别绕，直接说重点”“拆成我能照做的步骤”“别让我记前文”也属于自然语言表达需求。普通请求只覆盖当前任务及相关补充；“只这条”收窄到当前回复。

需要本会话跨主题持续时明确说：

```text
启用 relax go 模式，接下来都按这个方式。
```

停止时说“停止 relax go”“关闭这个表达模式”或模式控制语境中的 `normal mode`。只结束本技能模式，不卸载、不改默认、不停独立 tech-doc；引文中的停止词不执行。仅提到名称、讨论 ADHD／STC、否定启用、医学诊断和无表达需求的普通编码不激活。没有自动跨会话保存。完整边界及手动 opt-in 示例见 [启停说明](references/activation-and-scope.md)。

## 完整目录安装原则

本次**没有执行安装**。可从上述仓库获取完整目录；手动使用时，先按宿主现有文档确认它支持技能目录／相对资源读取，再在用户选定且不冲突的新位置放入**完整 `waa-relax-go/` 目录**。只复制 SKILL.md 会丢规则和词表，不能称作已安装完整技能。

1. 确认宿主、目标位置和安装范围，并保护该处已有用户文件。
2. 复制完整目录，保留 rules、dictionary、references、tools 和许可证；目标已有同名内容时先核对，不覆盖未知工作。
3. 让宿主读取 SKILL.md，并核对所有强制相对资源能读取。
4. 用一条明确请求检查实际效果；仅“文件存在”或 description 匹配不是实际模型激活证据。

不提供固定平台路径、slash 注册、init、hook、包管理器、模型 API 或默认写入脚本。不自动下载或安装 Node。没有 identified host consumer，所以没有装饰性 interface／manifest。

## 改编与冲突

- STC 是完整主体，规则与词表不是灵感摘要。G2 只用已提供／获准读取的术语表；不为缺表写治理。
- 词表按 scope 和真实含义判断，保留官方名称、像素对齐、闭环控制、定性观察与不确定性；不从例子编事实，不把“删除”一律写成永久丢失。
- 40 字句子、30 字步骤、3 层修饰、300 字分组和约 5 项摘要都是建议。完整解释、全部选项、七步操作与真实警告优先。
- i-have-adhd 的行为完整保留但有界改写：不推断诊断；问答／操作／交付各有首行；只有明确会话模式才持续；状态更新不双重旁白；时间有依据才估；无真依赖就停止。
- C10 保留结果／用户动作／知会区别和明确可用的[完整三段回执](rules/for-chat.md#c10)，简单交付省空段，不造待办与截止。

### 与 tech-doc 共存

技术／产品／界面成品适用且独立 `tech-doc-style-chinese` 可读取时，按真实发现机制加载它和适用参考。技术成品用专门风格，周围对话用本包；不可用就说明完整 tech-doc 检查未执行，不安装或假装读取。

独立基线默认弯引号“”；技术成品默认直角「」，项目与固定引用优先。实际 checker 有 `--style relax-go|tech-doc` 及 `--quotes`，不是只在说明里口头协调。`--style tech-doc` 不等于独立 tech-doc 全套检查；仍须人工复核 task mode、语义和表面。

### 旧规则迁移

不要同时把本包、原 STC、原 i-have-adhd 和旧 `waa-clear` 都设成相互竞争的默认。仓库更名和新版推送不会自动替换已安装的旧技能，也不改动原始技能、冻结来源或默认配置。已安装技能的迁移是单独任务：先核对宿主实际引用与权限，再由用户选择范围，保留用户配置。本包不自动取消任何旧技能或独立 tech-doc。

## 可选检查器

从包含本目录的位置运行手工示例：

```sh
printf '%s\n' '点击「保存」。像素对齐。' | node waa-relax-go/tools/check.mjs --style tech-doc --json
```

预期：`style` 为 `tech-doc`、`quotes` 为 `corner`、`errors` 为 `0`；“对齐”保留为上下文 warning，不出现 G17 错误。若返回 G17 引号错误或把术语当作确定错误，风格适配没有按预期运行。这个动作能验证可选 CLI 的分支，不验证模型激活。

读文件／stdin、四个 profile、text／Markdown／JSON、明确 exit code、warning 与内容绑定 Anti-Echo 均保留。tool 不自动修改输入，不能把报告 0 当成全文正确或渲染验证。路径符号链接不展开；若拒绝真实选定路径，说明拒绝而不绕过。全部用法和局限见 [tools/README.md](tools/README.md)。

**已验证最低支持版本：Node.js 26.13.0，本次 macOS 环境。** 上游源码门槛是 18+，本包保留该门槛，但 18 至 25 没有实际执行，兼容性未验证，不作支持声明。Prose 无 Node 依赖；不能执行工具时用完整人工复核并披露未运行。

| 语义场景 | 手工性质／反例和当前生产上下文示例，不是盲测、独立评估、医疗效果或一般模型服从 |
