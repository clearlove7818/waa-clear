# 完整词表与语境用法

本目录保留 STC 的全部 83 个 YAML 条目和完整字段／例子，YAML 与本次冻结输入逐字节一致。来源是 Daimonia 的 STC，规则和词表采用 CC BY 4.0；见 [完整许可](../LICENSE)和[来源通知](../THIRD_PARTY_NOTICES.md)。本指南改写用法，不改源词条。

| 文件 | 内容与读取条件 |
| --- | --- |
| [avoid.yaml](avoid.yaml) | 51 个不推荐写法；每次使用必须完整读取，再按场景挑选适用条目 |
| [recommended.yaml](recommended.yaml) | 29 个推荐词；文档、界面、动作或风险提醒适用时必须完整读取 |
| [terms.example.yaml](terms.example.yaml) | 3 个项目术语示例；用户请求模板时读取，不是实际项目的既有术语 |

条目排列沿用来源，不声称本项目测量过词频。例子均是构造演示，数字、名称、时限、原因与结果不得直接补入用户材料。

## 先判断含义，再选择写法

必须按 [G3](../rules/for-all.md#g3)、[G5](../rules/for-all.md#g5)、[G6](../rules/for-all.md#g6)、[G7](../rules/for-all.md#g7)执行以下裁决，而不是全局替换：

1. 先保护代码、命令、路径、URL、JSON 键和值、API 标识、固定引文、法律原文、官方拼写与用户指定字面量。引用两类中文引号都只是提及，不因其中的词触发替换。
2. 检查 `profiles`。未写或空数组表示所有场景；否则只应用于列出的 `for-chat`、`for-document`、`for-web-dev`、`for-instruction-writing`。不得把指令强度词禁令套到普通问答。
3. 以用户提供的项目术语和实际技术含义为准。例如像素对齐、网络链路、闭环控制、化学沉淀、统计相关和数据颗粒度有确切含义。首次说明陌生术语；保留术语不是豁免整句的模糊性。
4. 判断条目 `why` 所说的问题是否实际存在。确有含糊、冗余或混用才按 `use` 的方向修改；有用事实对比、定性观察和不确定性保留。审阅可以报告待确认，不能把不明含义说成已判定错误。
5. 用已有事实实现改法。不能从例句借 120 名用户、3 秒、15%、3 天等数字，也不能删除“非常”后编出“已提速”。草稿可标“【待补：…】”并列全部缺项；普通回复可写未知。强度词按原要求等级改，不把推荐升级为硬要求。

这些步骤是执行流程，不授予读取项目其他文件或修改规则的权限。术语表未提供时沿用已授权材料，缺表不触发扫描或自动建表。

### 推荐词表示用法约定，不表示产品事实

全部词义、近义区别和例子仍有效用于选择表达，但以实际对象和产品行为为前提。尤其需要核对以下组：

| 词组 | 必须核对的事实 |
| --- | --- |
| 删除／移除／清空 | 去掉的是对象、组成员还是容器内容；是否支持撤销／回收站。源条目的“删除＝永久”“清空回收站＝不可恢复”只是该约定下的例子，不能推出本产品不可恢复 |
| 保存／提交／发布 | 是存草稿、交处理，还是让目标读者可见；谁可见、何时处理不能照抄例句 |
| 取消／撤销／关闭 | 停止未完成操作、回到操作前、关闭表面分别是什么；取消可能保留部分数据，关闭也可能提示未保存内容，须按真实行为写 |
| 打开／启用／停用 | 显示页面与生效开关不同；停用是否保留数据、是否可恢复需产品依据 |
| 新建／添加／编辑 | 对象是否原本存在；不把已有对象添加操作改成创建 |
| 上传／导入／下载／导出 | 原样文件传输与格式／数据转换不同；准确保留实际转换和去向 |
| 检查／审核／确认 | 符合性判断、权限人员批准、用户同意操作不同；“确认”也可能是普通核实事实，先看语境，不新设批准门槛 |
| 同步／刷新／更新 | 两处一致、重新显示、版本／值变化不同；同步方向、冲突方式和周期没有资料就不补 |
| 失败 | 未达到预期结果；不据此断言零副作用、确定原因或恢复时间 |
| 警告／注意／说明 | 根据真实数据丢失／安全／不可撤销风险、操作失败风险、背景说明分级，不根据动作名称猜风险 |

技术成品的上下文处理见 [tech-doc 协作](../references/tech-doc-compatibility.md#lexicon)。独立基线同样保护真实含义，不用“技术风格”隐藏已确认的空话。

## 保留的字段

### 推荐词

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `word` | 推荐词 | 必填 |
| `pos` | 本条规定的词性 | 必填 |
| `meaning` | STC 用法约定中的含义，不覆盖产品事实 | 必填 |
| `not_same_as` | 近义词和各自区别 | 有则完整保留 |
| `example` | 用法示例，不是事实来源 | 必填 |
| `profiles` | 适用场景 | 无或空表示全部 |

例如“移除”保留对象本身，“清空”保留容器；若项目已有不同正式定义，按项目写并单独报告区别，不悄悄改产品功能。

### 不推荐写法

| 字段 | 含义 | 要求 |
| --- | --- | --- |
| `avoid` | 词或句式，多写法用 ` / ` 分隔 | 必填 |
| `type` | 类别 | 必填 |
| `why` | 不推荐原因 | 必填 |
| `use` | 改写方向，不是自动替换命令 | 必填 |
| `examples` | 完整 `before`／`after` 配对 | 必填 |
| `profiles` | 不推荐的场景 | 无或空表示全部 |

全部 12 类均保留：虚动词、程度词、模糊量词、含糊动词、营销词、行话、套话、口号句式、翻译腔、冗余、强度词、人称代词。含义分别是动作名词外壳、不清程度、不清范围、不清变化、空泛宣传、待翻译行业话、无信息固定开头、以气势替代事实、直译结构、不增信息修饰、规范强度、可能不明主体。每条具体原因和例子以 YAML 为准。

### 项目模板

`term` 是首选名称，`meaning` 是项目含义，`not` 列不使用的名称，`en` 是英文展示名。模板的“项目／成员／报告”只是例子，不能把真实项目“报表”强行改成“报告”。创建或更新实际术语表须单独处于授权范围。

## 机器数据与维护

`tools/check/data/avoid.json` 和 `recommended.json` 保留全量 YAML 字段，供无第三方运行依赖的检查器使用。JSON 是派生数据，不是手工删减词表。维护时必须逐条对照 YAML，并核对全部键、数组顺序、例子和区别；本包不附安装、自动生成器或配置写入器。增加词条前先检查是否重复，推荐词每个词只一条，新增不推荐条目须有真实用法解释及至少一组演示。

检查器匹配不代表词义错误，也不自动替换。全部含义相关词表匹配给上下文建议；`--style tech-doc` 明确启用技术语境提示，`--quotes` 选择排版约定。人工仍要检验语义、事实和 scope；详见 [工具边界](../tools/README.md)。
